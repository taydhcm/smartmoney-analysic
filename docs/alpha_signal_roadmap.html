Chi Tiết Các Module Cốt Lõi

S1

Wyckoff VSA Engine — Cải tiến toàn diện so với hiện tại

Viết lại detect_accumulation_phase()

Phân biệt được 4 loại tích lũy tại VN: Smart accumulation / Sector rotation / Bẫy retail / Tự nhiên. Thêm VSA (Volume Spread Analysis) và time-at-price.

Output features

  • wyckoff_phase: A/B/C/D/DIST/NONE
  • phase_duration_d: số phiên trong phase hiện tại
  • cause_strength: tổng vol tích lũy / vol TB
  • spring_quality: 0–1 (Spring thật vs giả)
  • lps_detected: Last Point of Support flag
  • effort_result: effort(vol) vs result(price)
  • no_supply_flag: narrow spread + low vol
  • stopping_vol: vol đột biến tại đáy

Cải tiến vs code cũ

  • Phase B: bắt buộc ≥ 10 phiên (không phải 1 window)
  • Spring: vol TẠI đáy < vol TB → Spring thật
  • LPS: test sau breakout, vol thấp + giá ≥ breakout
  • Vol profile: vol ở 1/3 dưới range > vol 1/3 trên
  • Cause strength: Point-and-Figure column proxy
  • Adaptive window theo market cap bucket
  • Phân biệt Distribution vs Accumulation bằng S4
# Interface output S1 — WyckoffSignal dataclass class WyckoffSignal: phase: Literal["A","B","C","D","DIST","NONE"] phase_duration: int # số phiên đang trong phase này cause_strength: float # [0,∞) — tích lũy càng dày càng cao spring_quality: float # [0,1] — 1.0 = Spring hoàn hảo lps_detected: bool no_supply: bool stopping_vol: bool effort_result: float # >1 = effort > result = accumulation pattern score: float # [0,1] composite Wyckoff score entry_signal: Literal["LPS_BUY","SPRING_BUY","PHASE_D_BUY","WATCH","AVOID"]
S3

Market Regime Engine — Bộ lọc quan trọng nhất

5-state machine · Dynamic threshold

5 Regime states

  • BULL: VN30 > SMA20, ADX > 20, breadth > 60%
  • BULL_WEAK: VN30 > SMA20, ADX 15–20
  • NEUTRAL: VN30 trong ±2% quanh SMA20
  • BEAR_WEAK: VN30 < SMA20, ADX 15–20
  • BEAR: VN30 < SMA20, ADX > 20, breadth < 40%

Threshold theo regime

  • BULL: P_min = 0.65, max_pos = 3
  • BULL_WEAK: P_min = 0.68, max_pos = 2
  • NEUTRAL: P_min = 0.72, max_pos = 1
  • BEAR_WEAK: P_min = 0.80 (cực chọn lọc)
  • BEAR: DISABLE — không vào lệnh long
S4

Smart Money Flow Engine — Phân biệt "ai đang mua"

Phụ thuộc D0.2 · Cần ≥ 5 phiên lịch sử

Features từ KBS history (D0.2)

  • foreign_net_1d: net buy/sell hôm nay
  • foreign_net_5d: tích lũy 5 phiên gần nhất
  • foreign_streak: số phiên mua ròng liên tiếp
  • foreign_buying_divergence: mua nhưng giá flat
  • tu_doan_net_5d: tự doanh tích lũy 5 phiên
  • alignment_score: ngoại + tự doanh cùng chiều
  • room_pct_left: % room ngoại còn lại

Scoring logic

  • Ngoại mua ròng 3+/5 phiên → +0.30 score
  • Tự doanh cùng chiều ngoại → +0.20
  • Buying divergence (vol↑ price flat) → +0.25
  • Room < 5% → CẢNH BÁO (không còn upside ngoại)
  • Ngoại bán mạnh trong uptrend → red flag –0.40
  • Cả hai cùng mua → signal mạnh nhất tại VN
S5

Entry Timing Engine — Vào đúng điểm, SL không bị quét noise

Output: entry zone + SL price + target price + R/R ratio

Support / Resistance

  • support_20d: low_20d × 0.99
  • resistance_20d: high_20d
  • price_in_range: (close–low)/(high–low) → 0=đáy
  • dist_to_support_pct: % từ close đến support
  • dist_to_resist_pct: % từ close đến resistance
  • risk_reward_ratio: target_dist / sl_dist

SL Survival Analysis

  • atr_14: Average True Range 14 phiên
  • sl_buffer_atr: (close – support) / atr_14
  • sl_buffer < 1.5 → SKIP (SL quá gần, noise sẽ quét)
  • suggested_sl: max(support_20d, close – 5%)
  • suggested_target: close + R/R × sl_dist
  • entry_zone: [close × 0.99, close × 1.005]

M2

Label Creator — Path-dependent, phản ánh trading goal thực

Ngày đầu tiên cần làm — toàn bộ hệ thống phụ thuộc vào label đúng
# Label chính: đạt target VÀ không chạm SL trong hành trình 5 phiên path_max = max(close[T+1..T+5]) / close[T] - 1 # max gain path_min = min(close[T+1..T+5]) / close[T] - 1 # max drawdown y_main = 1 if (path_max >= 0.05) and (path_min > -0.05) else 0 # Labels phụ (analysis + multi-output model) days_to_target = first_day_reaching_5pct_gain # holding period tối ưu sl_hit_flag = (path_min <= -0.05) # có bị quét SL không? max_gain_5d = path_max # upside tiềm năng thực tế

Kỳ vọng label distribution

  • y=1 (đạt target, không SL): 15–20%
  • y=0 (chạm SL hoặc không đủ gain): 80–85%
  • Cải thiện vs label cũ: 9% → 15–20%
  • scale_pos_weight ≈ 4–5x

Lưu ý kỹ thuật

  • Shift(–5) → drop 5 rows cuối mỗi ticker
  • Chỉ dùng daily close (phù hợp ATO entry)
  • Test target_threshold 3%, 5%, 7% → chọn optimal
  • SL_threshold: HOSE 5%, HNX 6%, UPCOM 7.5%

Hybrid Self-Learning Architecture — Chiến Lược Tự Cải Thiện

Không dùng Online Learning thuần túy (quá ít data, mất điểm mạnh của LightGBM). Thay vào đó: LightGBM Base + Rolling Calibration Drift — giữ độ chính xác cao của batch model, thêm khả năng thích nghi theo thời gian thực.

🧩

Bước 1 — Giữ LightGBM (Batch) — Retrain 2 tuần/lần

LightGBM vẫn là core model. Chạy retrain_v5.py mỗi 2 tuần trên full VN30 6m data. TimeSeriesSplit cross-validation, 35 features, artifact versioned. Batch model giữ được sức mạnh ensemble của gradient boosting — không hy sinh để lấy tính online.

💾

Bước 2 — E5 Outcome Tracker — Ghi signal → kết quả T+5 thực tế

Mỗi signal phát ra được ghi vào SQLite signal_log.db: ticker, date, p_calibrated, 35 features snapshot. Lúc 15:15 hàng ngày: auto-check outcome T+5 (actual_return, hit_target). Sau 5 ngày → label thực tế sẵn sàng cho E6. Đây là data quý nhất — production predictions với label thực tế.

🔄

Bước 3 — E6 Rolling IsotonicRegression — Calibrator thích nghi hàng tuần

Mỗi tuần: lấy 90 outcomes gần nhất từ signal_log.db → re-fit IsotonicRegression → save alpha_calibrator.pkl. LightGBM model KHÔNG đổi — chỉ calibration layer thích nghi. Xác suất hiển thị trên UI tự điều chỉnh khi thị trường drift mà không cần retrain model nặng.

⚠️

Bước 4 — Drift Alert — Cảnh báo khi model cần retrain

Theo dõi rolling precision (30 outcomes gần nhất). Nếu < 0.30 trong 10 ngày liên tiếp → banner đỏ trên UI + log cảnh báo → user trigger manual retrain_v5.py. Sau retrain: E6 rolling calibrator reset và bắt đầu lại. Không tự động retrain để tránh catastrophic forgetting.

So sánh với Online Learning thuần

  • Giữ LightGBM → AUC cao hơn SGD/River ML
  • VN30 chỉ 2–5 signals/ngày → quá ít cho online learning
  • Calibration rolling nhẹ hơn nhiều so với retrain full model
  • Drift alert kịp thời thay vì model tự drift âm thầm
  • Dễ debug: biết chính xác tại sao calibrator thay đổi

Data flow Hybrid

  • Signal phát → signal_log.db (ngay lập tức)
  • T+5 → auto label → outcome row completed
  • Mỗi tuần: 90 outcomes → refit calibrator
  • Mỗi 2 tuần: full LightGBM retrain nếu OK
  • Precision < 0.30 × 10 ngày → alert → manual retrain

📋 Nguyên Tắc Kiến Trúc (Architecture Principles)

01
Độc lập từng module
Mỗi Signal Engine test riêng. Thêm module không break module cũ. Interface contract cố định.
02
Zero look-ahead
Tất cả features dùng shift() đúng. Walk-forward CV mandatory. Không có exception.
03
Data trước, model sau
D0.2 logger phải chạy ngay hôm nay. Mỗi ngày không có data = mất 1 sample không bù được.
04
Hard rules không override
Regime BEAR = không vào. SL buffer < 1.5 = không vào. Không có exception dù P cao.
05
Gate-based deployment
Backtest không pass → không go-live. Mỗi sprint kết thúc bằng validation.
